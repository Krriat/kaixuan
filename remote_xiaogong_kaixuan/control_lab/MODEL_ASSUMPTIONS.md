# 模型假设与辨识计划

## 为什么第 7 轴用 0.02 kg·m²

已知末端没有安装工具或负载。URDF 的 `left_link7/right_link7` 是输出坐标系，
`left_ee/right_ee` 保留质量 1e-6 kg、惯量 1e-11 kg·m² 的微小球形坐标标记。
这个标记并不代表电机转子。末端没有负载，电机和减速器仍有转动惯量。

本次用常数对角附加惯量近似：

\[
J_{a,7}=0.02\;\mathrm{kg\,m^2},\qquad
M_{eff}(q)=M_{URDF}(q)+\operatorname{diag}(J_a).
\]

第 7 轴现有规格记录是 KGU-11、减速比 N=101。若这项全按转子折算解释：

\[
J_{motor}\approx \frac{0.02}{101^2}
=1.9606\times10^{-6}\;\mathrm{kg\,m^2}.
\]

这一量级相当于假设一个约 40 g、半径约 10 mm 的实心圆盘转子，
`J=mr²/2`。**圆盘尺寸是解释初值量级的假设，并非该电机的真实结构资料。**
所以 0.02 是可替换的起点，不是型号参数或估计置信区间。
先对 0.01、0.02、0.04 做敏感性实验，再用厂家转子数据或等效惯量辨识替换。

这种常数对角 armature 表示局部关节的附加动能 `0.5*Ja*dq²`，没有增加重力势能；
近似忽略完整转子模型的轴间耦合、柔性和齿隙。
本次没有修改真实硬件重力控制器，也没有把这项惯量写成额外的末端质量。

Pinocchio 适配器显式执行：

```text
M = CRBA(URDF, q) + diag(Ja)
g = computeGeneralizedGravity(URDF, q)
h = nonLinearEffects(URDF, q, dq) = c + g
tau = RNEA(URDF, q, dq, ddq) + Ja * ddq
```

将来若使用 Pinocchio 自身的 armature/rotor 字段，就删除这里的手动加项并重新交叉验证，
避免添加两次。MuJoCo 中配置已是输出侧值，`motor gear=1`，不能再次乘 N²。
固定右臂时，其第 7 轴 armature 不参与当前七自由度系统。

## 当前参数可信程度

| 参数 | 当前使用方式 | 后续工作 |
| --- | --- | --- |
| 坐标、轴方向、零位 | 沿用电脑端 URDF；left_joint2=-Z，left_joint6=+Z | 本地可视化与正向运动学复核；不再额外翻转驱动方向 |
| 连杆质量、质心、惯量 | URDF 的 CAD 参数 | 静态多姿态重力校核，必要时辨识可辨识的组合参数 |
| 工具负载 | 无附加工具；保留 URDF 微小标记 | 有真实工具后再填质量、质心、惯量 |
| J7 armature | 0.02，工程初值 | 厂家转子参数 × N²，或直接辨识输出侧等效惯量 |
| J1–J6 armature | 未额外建模 | 不能理解成真实值为零；动态控制迁移前评估影响 |
| 摩擦 | 仿真基线设为零 | 核对现有低速辨识适用姿态/速度，逐步加入被动摩擦 |
| 延迟 | 默认 0；支持整数物理步延迟 | 端到端测时，EtherCAT 周期不等于总响应延迟 |
| 扭矩响应 | 默认理想；支持一阶时间常数 T | 小幅实验估计，`fc≈1/(2πT)` 只对应一阶模型 |
| 扭矩刻度 | 控制层 Nm；硬件沿用电流推算值 | 外部已知力臂/力矩或合适测量设备校核 |
| 力矩限制 | 现有重力模式限制 [13.6,13.6,8,8,3,3,3] Nm | 并非电机峰值能力，也未验证适合所有新控制任务 |
| 速度限制 | 90°/s，仿真超限退出 | 是运行保护阈值，不是内置速度调节器 |
| 碰撞/接触 | 关闭，STL 仅用于显示 | 接触任务前准备简化碰撞几何、接触与摩擦参数 |

配置中的 120° 相对位移和硬件力矩斜率是**参考快照**。
当前仿真未实现 120° 锁存；默认未启用斜率限制。可把 `actuator.torque_slew_nm_s`
设成 [6.8,6.8,4,4,1.5,1.5,1.5] 启用仿真的逐步限制。
启用后从 0 力矩起步，重力支撑可能来不及建立，需设计启动过程；不能为了仿真静止而隐藏初始化差异。
这些仿真假设、硬件启动准备/重力渐入流程都应在实机迁移阶段单独检查。

## 摩擦和软件阻尼分开

真实左臂已有低速、局部姿态的摩擦辨识，并已加入限幅的摩擦辅助。
它使用电流推算的名义输出力矩，范围大致为 J1 0.5–4°/s、J2/J3 0.5–2°/s、
J4–J7 0.5–1.5°/s；未验证 90°/s 全范围、全姿态或被动反拖。
最近 URDF 与辨识记录的模型哈希不同，复用前要比较具体动力学变更。

仓库参考文件：`xiaogong_kaixuan/src/kaixuan_can_hardware/config/left_arm_friction_identified.yaml`。
它不作为本目录的运行依赖。现有 `kaixuan_bam` 是另一套早期位置执行器 bootstrap，
其整机几何惯量、摩擦比例和 1 ms 延迟不是本次 CST 模型的辨识结果，不能直接合并叠加。

物理模型中的耗散项记为 `tau_f(dq)`；控制器的人工软件阻尼记为 `-B*dq`。
如果两者都加入，必须在日志和方程中分别列出，不能拿控制增益 B 当作辨识得到的物理黏性系数。

## 什么时候补辨识

先运行理想模型中的算法实验；在每个算法迁移真机之前，按影响优先级补数据：

1. 对齐方向、角度/速度单位、Nm 刻度和固定基座重力方向。
2. 多姿态静态检查 G(q)，明确工具负载和质心。
3. 对目标实验轴辨识等效惯量/低速摩擦，用留出的轨迹验证。
4. 测执行器端到端延迟、扭矩跟踪响应；比较有/无延迟和带宽限制的闭环表现。
5. 需要较快七轴运动时，扩展动态惯量/耦合校核；接触阶段再补接触几何与摩擦。

慢速准静态数据无法单独辨识惯量；需要有足够加速度激励。
`tau-g-c = J_eff*qdd + tau_f` 中的刻度误差、摩擦和加速度噪声可能互相混淆，
不要只凭一次阶跃把所有误差都拟合进 J。无末端负载的第 7 轴可以先辨识总等效惯量，
不必强行把转子、齿轮、输出轴的各部分独立分离。

参考：[MuJoCo armature 的折算定义](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#body-joint-armature)、
[MIT 系统辨识讲义](https://underactuated.mit.edu/sysid.html)。

## 运行

在 Orin 的两个终端分别执行环境准备：

```bash
cd /home/agxorin/cxl/kaixuan/xiaogong_kaixuan
source /opt/ros/humble/setup.bash
source install/setup.bash
```

如需重新安装脚本：

```bash
colcon build --symlink-install --base-paths src/kaixuan_can_hardware src/kaixuan3_config --packages-select kaixuan_can_hardware kaixuan3_config
source install/setup.bash
```

终端一启动实际硬件通讯：

```bash
ros2 launch kaixuan3_config cst_cartesian_test.launch.py
```

等待日志显示 `torque_controller` 已激活。这个 launch 固定选择真实硬件、左臂七轴、
CST、七轴故障联停，以及 `cartesian_torque_limits.yaml` 的运动实验限制。
其中第 1、3、4 轴力矩幅值为 20 N·m，其他轴幅值及速度、位移阈值沿用 `gravity_limits.yaml`；力矩变化率独立配置，
以便速度反馈在克服静摩擦后能及时减小力矩。原重力补偿配置不变。
**单独启动 launch 只建立 OP/CST 通讯，不发送有效力矩命令，不使能电机。**
不要同时运行另一个 `ros2_control_node` 或重力补偿 launch。

终端二先检查，下面命令没有力矩发布器：

```bash
ros2 run kaixuan3_config cst_cartesian_z.py
```

检查通过后执行一次并停在终点：

```bash
ros2 run kaixuan3_config cst_cartesian_z.py --execute
```

或者完成测量后沿参考路径返回，再回到本次使能前姿态并去使能：

```bash
ros2 run kaixuan3_config cst_cartesian_z.py --execute --finish return
```

两条执行命令都会真正运动。首次调试入口要求初始七轴均在零位 ±10° 内，
准备段约 30 秒，直线运动 20 秒，另外还有使能、重力爬升和等待稳定的时间。
默认终点保持会继续输出支撑力矩，不会自动变成零力矩。
`Ctrl+C` 会使力矩命令失效并停用 `torque_controller`，下层输出零力矩/CW6；
**CW6 不等于已经确认机械刹车抱住，停止前需托住手臂。**
正常返回或停止后控制器会变为 inactive；下一轮可重启 launch。
程序不会自动清故障、自动重新使能或接管已有力矩发布器。

如果停止后的姿态超出默认 ±10° 启动范围，可显式指定上一轮的
`final_standby.json` 重新开始实验，例如：

```bash
ros2 run kaixuan3_config cst_cartesian_z.py --execute --finish return --resume-from log/上一轮目录/final_standby.json
```

该入口要求保存记录为无故障、去使能、零目标力矩且静止的状态，当前编码器与
记录各轴相差不超过 0.25°，当前同样静止；模型启动重力不得超过各轴上限的 25%。
随后从当前姿态重新规划、检查整条准备段和直线段。它不会沿用旧轨迹进度，
也不会更改默认启动范围、跟踪误差阈值或速度保护。

## 直线从哪里来

设起始关节角为 \(q_0\)。Pinocchio 从当前控制器的 `robot_description` 计算
末端位置 \(p_0=f(q_0)\) 和朝向 \(R_0\)，不依赖离线文件是否与真机版本相同。
本模型的起终点约为：

```text
起点 world: [0.47410405, 0.29824385, 0.52584026] m
终点 world: [0.47410405, 0.29824385, 0.62584026] m
```

20 秒内使用五次时间插值：

\[
u=t/T,\quad s(u)=10u^3-15u^4+6u^5,
\qquad p_d(t)=p_0+s(u)[0,0,0.10]^T,\quad R_d(t)=R_0.
\]

因此 X、Y 和朝向保持不变，Z 平滑增加；起终点速度和加速度为零。
每隔 20 ms 用上一个解作种子求连续逆运动学，求得关节轨迹 \(q_d(t)\)，
再用三次样条得到 \(\dot q_d,\ddot q_d\)。程序加密采样检查末端几何误差、关节范围、
速度、名义动力学力矩，以及采样自碰撞。七轴对应六维末端任务有冗余，
本实验选择连续的局部逆解，没有进行全局姿态优化。

用户已确认只标定了左臂，因此自碰撞检查只覆盖左臂与身体、左臂自身，
并沿用 SRDF 的排除项。**右臂没有纳入自动碰撞检查**，不能把未标定的右臂
编码器映射结果当成实际空间姿态。用户需确认右臂与其他物体不在左臂路径中。
当前用户已确认右臂处于其他姿态、左臂区域空旷。此确认不适用于以后改变的环境。
URDF 几何本身也有误差，离散自碰撞检查只是模型检查，不是现实无碰撞保证。

## 原 PID 基线如何跟踪

本节描述显式选择 `--config .../cst_cartesian_test.yaml` 的旧外环。
默认 TV-LQI 的控制律与 Riccati 推导见 [CST_LQR.md](CST_LQR.md)。

真实机器人近似满足：

\[
M(q)\ddot q+c(q,\dot q)+G(q)+\tau_f=\tau_{cmd}+\tau_{ext}.
\]

本版每个控制周期用编码器的 \(q,\dot q\) 计算：

\[
\tau_{ff}=\operatorname{RNEA}(q,\dot q_f,\ddot q_d)
          =M(q)\ddot q_d+c(q,\dot q_f)+G(q),
\]

\[
\tau_{raw}=\tau_{ff}
   +K_p(q_d-q)+K_d(\dot q_d-\dot q_f)+\tau_I,
\qquad \dot\tau_I=K_i(q_d-q).
\]

这里的增益直接把关节误差变成 N·m；区别于离线理想示例中先计算加速度反馈、
再整体乘 \(M\) 的形式。RNEA 给出加速度前馈、科氏/离心项和重力项；
比例项拉回位置误差，微分项抑制速度误差，受限积分项逐渐纠正摩擦和模型偏差。
速度经过 5 ms 一阶滤波。积分有独立上限；输出触及力矩或变化率限制时，
如果积分会继续加重饱和，就暂停该分量的积分。

最后对总力矩限幅并限制变化率，然后发送给已有 `TorqueController`。
运动实验的变化率为 `[136,136,160,160,60,60,60]` N·m/s；初始重力仍在 5 秒内爬升。
第一次实机准备段使用重力模式的低变化率时，J3 的期望力矩已经降到约
0.82 N·m，而受 4 N·m/s 限制的发送力矩仍为约 3.83 N·m，随后触发本实验
20°/s 退出条件。因此本版降低了 P/I 增益、增加速度阻尼，并使用独立变化率。
更快变化率既允许及时减力矩，也允许更快增力矩；它不是通用安全参数，
应连同反馈增益、负载和退出条件一起验证。
不会再同时运行 `GravityController`，否则会重复补偿或争用接口。
没有直接添加之前辨识的库仑摩擦前馈；局部辨识结果不能保证覆盖整条路径。
此 PID 基线除第 1 轴局部整定外仍使用工程初值，不是优化求得的增益。
J7 额外输出端惯量 0.02 kg·m² 仍是工程估计，仅在 RNEA/M 中加入一次。

用户已指出 URDF 不够精确。因此将模型用于前馈、将实际编码器用于反馈，
同时保留跟踪退出条件；不能开环播放一串 Pinocchio 力矩。
反馈和积分能减小有界动力学偏差造成的跟踪误差，但不保证任意模型误差下稳定。
几何误差与动力学误差也不同：几何/零位不准时，即使关节跟踪很好，
现实末端仍可能偏离理想直线，需要外部测量或几何标定来判断。

“只使用力矩模式”指驱动接收的是力矩；软件仍然需要位置和速度反馈。
只发送重力补偿 \(G(q)\) 不会自动走直线，直线参考和跟踪反馈缺一不可。

## 通讯与停机

```text
编码器 → EtherCAT TxPDO → ros2_control /joint_states
                               ↓ 200 Hz 本机 Python 反馈计算
                         七个输出关节力矩 N·m
                               ↓ /torque_controller/commands
TorqueController → effort 接口 → 1 kHz 硬件守护/限幅 → EtherCAT RxPDO
                                                    0x6071 目标力矩
```

新鲜的全零命令触发现有使能序列 6 → 7 → 15；七轴进入 Operation Enabled
后，程序在 5 秒内爬升到重力和反馈力矩，然后开始准备段。
驱动仍处于模式 10/CST，其内部执行电流/力矩闭环。软件中的 (q_d) 从不作为
驱动位置命令发送，所有运动由总力矩产生。

每周期检查反馈和采样时间；Python 反馈超过 50 ms、循环间隔超过 50 ms、
诊断超过 0.7 s、跟踪误差超过 8°、实际速度超过本实验的 45°/s 等都会中止。
这些是本实验的额外退出条件，**硬件现有 90°/s、120° 相对位移和力矩保护保留**。
命令发布停止后，下层还有 100 ms 的 topic watchdog；硬件故障会让七轴联停。
Python/ROS topic 是软实时实验链路；不能用它声称具备工业实时确定性。
本实验速度退出阈值原为 20°/s，现按用户要求调整为 45°/s。

## 如何判断实际成功

输出保存在工作目录 `log/cst_z_时间/`：

- `plan.json`：实际初始角、URDF 哈希、路径、参数、限制、自碰撞检查。
- `active_robot.urdf`：本次运行使用的完整模型。
- `samples.csv`：各阶段实际角度/速度、参考角度/速度、请求力矩、限幅前力矩、积分、测得力矩和末端位置。
- `result.json`：直线实际位移、最大横向偏差、终点偏差、朝向偏差、是否达到阈值。
- `status.json`：完成/中止原因，是否真正发布过力矩。
- `stop_state.json`：退出后的驱动诊断和关节状态。

默认验收阈值是终点误差 ≤5 mm、最大横向误差 ≤5 mm、朝向误差 ≤1°。
运动完成但超出阈值会明确记为失败，不能只看“移动了”就认为精确走了直线。
末端“实测”来自 **真实编码器 + URDF 正运动学**，不是外部相机或测量仪。
若模型几何、零位、关节弹性或力矩尺度不准，仍需外部测量验证现实精度。

数值回归检查可运行：

```bash
OPENBLAS_NUM_THREADS=1 python3 -m unittest discover -s src/kaixuan3_config/test -p 'test_cst_*.py' -v
```

16 项数值/配置测试通过；这些测试不打开 EtherCAT、不使能电机。
它们验证直线/朝向、准备段边界、力矩余量拒绝、
RNEA/惯量一致性、限幅/变化率/积分抗饱和、初始零力矩和真实硬件类型检查。
还检查了仅第 1、3、4 轴力矩幅值覆盖为 20 N·m，其他幅值、硬件速度和位移等物理边界保持既有配置。
停止记录恢复检查会拒绝不匹配姿态、非静止反馈和仍使能的保存记录。
LQR 检查还覆盖固定输入线性化、Riccati 残差、耦合增益、权重变化、
恒定输入扰动消除、增益回放和积分限幅/段间切换。

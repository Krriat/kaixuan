## 控制结构

采用带积分扩展的时变 LQR（TV-LQI）。优化状态为

```
e = [q - qr; dq - dqr; z],     z_dot = q - qr
tau_r = RNEA(qr, dqr, ddqr)
tau = tau_r - K(t) e
```

位置、速度、积分误差单位分别为 rad、rad/s、rad·s；力矩是名义关节端 N·m。
前馈使用参考状态，重力只包含一次，不额外叠加旧 PID 或另一份重力补偿。
`K(t)` 是 7×21 的耦合矩阵，来自优化，非人工指定的逐轴 P/D/I。

令 `h(q,v)=c(q,v)+G(q)`，在参考状态和输入 `tau_r` 附近线性化：

```
delta_q_dot = delta_v
delta_v_dot = -M^-1 (dRNEA/dq delta_q + dRNEA/dv delta_v) + M^-1 delta_tau
z_dot = delta_q
```

Pinocchio `computeRNEADerivatives(qr,dqr,ddqr)` 在固定参考加速度下求导；
这样包含 `(dM/dq) ddqr`，而不是只求重力梯度。
额外 armature 只加进质量矩阵和 RNEA 一次。
模型每 50 ms 重新线性化，局部模型使用精确零阶保持离散化；
Riccati 反向递推和增益回放的标称周期均为 5 ms / 200 Hz。

优化目标：

```
sum (e_k.T Q_k e_k + delta_tau_k.T R delta_tau_k) + e_N.T P_N e_N
```

`Q` 的位置块包含 `J.T W_task J` 和关节误差权重，速度及积分块分别加权。
`R` 惩罚相对动力学前馈的修正力矩。终端 `P_N` 由终点 DARE 求出；
各运动段分别递推，静止段使用相应姿态的稳态 LQI。
每一步的反馈及价值矩阵为

```
K_k = (R + B_k.T P_(k+1) B_k)^-1 B_k.T P_(k+1) A_k
P_k = Q_k + K_k.T R K_k + (A_k-B_k K_k).T P_(k+1) (A_k-B_k K_k)
```

设计过程检查矩阵正定、Riccati 残差、终端极点及采样姿态的局部闭环极点。
规划、碰撞检查和增益求解全部发生在发送第一条力矩前。

## 调参含义

权重以物理尺度表达；相应权重为尺度平方的倒数。
尺度表示优化偏好，不是硬性允许误差。

| 配置 | 调小后的主要倾向 |
|---|---|
| `ee_position_scale_m` | 更重视末端位置 |
| `ee_orientation_scale_rad` | 更重视末端朝向 |
| `joint_position_scale_rad` | 更重视对应关节位置 |
| `joint_velocity_scale_rad_s` | 更重视速度误差，通常增加阻尼 |
| `integrated_error_scale_rad_s` | 更快消除持续位置偏差，同时更易积累积分 |
| `torque_scale_nm` | 更昂贵地使用对应关节修正力矩 |

`effort_weight` 增大则整体增加力矩代价。每轮修改后重新计算所有相关增益，
从原地保持和准备/返回开始验证，再测整条直线路径。
不能根据单个对角元素断定耦合矩阵的整体强弱。

## 实机入口

```
ros2 launch kaixuan3_config cst_cartesian_test.launch.py

export OPENBLAS_NUM_THREADS=1

# 默认只检查，不使能、不发送力矩。
ros2 run kaixuan3_config cst_cartesian_z.py

# 仅验证当前位置保持，随后卸载力矩并去使能。
ros2 run kaixuan3_config cst_cartesian_z.py --execute --stop-after hold

# 到准备姿态，再返回本次使能位置，不执行 +Z 路径。
ros2 run kaixuan3_config cst_cartesian_z.py --execute --stop-after approach

# 准备姿态、固定朝向 +Z 10 cm、逆路径返回，然后去使能。
ros2 run kaixuan3_config cst_cartesian_z.py --execute --finish return
```

默认仍要求接近已标定零位。非零位重启须使用经过验证、与当前静止去使能姿态匹配的
`--resume-from final_standby.json`，并通过原启动重力裕量检查。
上一次试验会停用 `torque_controller`；仅在已确认静止、去使能、零目标、无故障时
重新激活桥接控制器，再执行下一轮。桥接激活本身不发送有效力矩。

配置 `execution_thread` 只在规划结束后将调用执行线程设为 CPU5/FIFO20，
已有 DDS 线程保持原调度；退出时恢复。权限或 CPU 不满足会在使能前退出。
这减少 Python 调度停顿，不提供硬实时保证。
使能前先完成一次循环垃圾回收；有限次往返/保持测试期间暂缓循环垃圾回收，
停止输出并停用桥接控制器后恢复。默认无限终点保持模式保留循环垃圾回收，避免长期累积循环对象；
本轮时序数据来自 `--finish return` 的有限次执行，不能套用到无限保持模式。
第一轮完整测试曾因 118.8 ms 停顿退出，根因尚未被证明；不能把之后一次无超时视为长期确定性保证。
各周期的 spin、检查/图查询、计算、发布和 FK/记录耗时上限写入 `status.json`。

## 保护及模型边界

原总力矩限幅、力矩变化率、45°/s 实验速度保护、90°/s 硬件速度保护、
120° 相对位移保护、8° 跟踪误差和通信看门狗保留。
积分反馈力矩单独限幅，发生输出/变化率饱和时冻结继续推向饱和的积分分量。
切换运动/静止段时，保留积分力矩，重新映射积分状态以避免力矩跳变。
限幅、抗饱和和斜坡是优化器外的保护，因此接近约束时不再是无约束 LQR 最优解。

名义模型不包含经过独立验证的转子折算惯量、摩擦、执行器带宽或传输延迟。
本轮曾用力矩/加速度记录做探索性拟合；惯量结果随平滑窗口而变化，不能当成完成辨识。
第 3–6 轴暂以 `[0.20, 0.20, 0.02, 0.04]` kg·m² 作为 LQR 实验模型的额外等效惯量，
第 7 轴保留原 0.02。它们是待验证的试验估计，未改动 URDF、厂家参数或旧 PID 配置。
速度反馈经过现有软件滤波；名义局部极点不能证明含延迟、摩擦和模型误差的实机稳定。
时变增益本身也不保证摩擦越障后的超调消失；必须用实机反向试验验证。
仅左臂已标定；碰撞检查不覆盖未知右臂姿态及外部环境。
末端精度来自编码器与活动 URDF 的 FK，没有外部测量。

每轮输出 `plan.json`、`lqr_design.json`、`lqr_gains.npz`、`samples.csv`、
`result.json`（到达相应阶段时）、`status.json` 和 `stop_state.json`。
保持/准备阶段的 `accepted` 仅针对相应局部阶段，不代表直线精度通过。
